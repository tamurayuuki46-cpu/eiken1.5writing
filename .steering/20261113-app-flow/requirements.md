# requirements.md — 画面の手前の進行役(Flow)

## 1. 目的
- なぜやるか: Core(学習ロジック)と Persistence(保存)は部品としてそろったが、「起動 → 練習 → 保存 → 再起動 → 復元」の順番と、
  保存失敗・ファイル破損のときの約束(仕様 v1.0 12・13章)を守る役がまだ無い。WPF に書くとクラウド(Linux)でテストできず、約束の抜けに気づけない。
- 終わったときの状態(Outcome): WPF は「今の画面の状態を表示し、利用者の操作を進行役に渡す」だけで MVP の流れが動く。
  流れと失敗時の約束は、本物のファイルを使ったテストで Linux・Windows の両方で確かめられている。

## 2. 範囲
- やること:
  - 新しいプロジェクト `EikenSpelling.Flow`(net10.0、Windows 非依存。Core・Persistence を参照)と、そのテスト
  - 起動: 設定の読込 → 単語データの読込・検査 → 学習記録の読込。結果に応じた画面の状態(通知・選択・終了のみ)
  - 未完了セッションの「再開」「終了して新しく始める」(v1.0 12.2)
  - 練習: 出題の選択 → 開始 → 出題 → 回答 → 判定 → 保存 → 次へ → 再練習 → 結果
  - 保存失敗時: 次へ進まない・回答を保持・再保存・二重記録しない(v1.0 13.3)
  - 両方破損時: 「新しい記録で開始」「終了」(確認後にだけ新規作成。v1.0 13.5)
  - 結果画面の集計(`SessionSummary`。通常問題の正答数・誤答単語・再練習の結果・苦手状態の変化。v1.0 16.1)
- やらないこと:
  - WPF の画面・音声・タイマー表示(次のタスク)。フラッシュ表示の秒数の計時も WPF 側
  - 苦手一覧・学習状況の表示用データ(別タスク)
  - 設定画面での変更と settings.json への保存(別タスク)。今回は練習ごとの選択を引数で受け取る(design 4.4)
  - 同梱する単語データ(初期100語)の作成。テストは小さなテスト用データで行う
  - 手動バックアップ・エクスポート(v0.1 対象外)
  - 二重起動の防止(WPF の名前付き Mutex。DECISIONS.md)

## 3. 機能要件
| # | 内容 | 優先度 | 入力 | 出力 |
|---|---|---|---|---|
| R1 | 起動: 設定 → 単語データ → 学習記録の順に読み、最初の画面の状態を決める | Must | 保存先フォルダ、単語データの JSON、使えるモード | 画面の状態(ホーム / 再開の選択 / 通知 / 両方破損の選択 / 終了のみ) |
| R2 | 起動時の通知: バックアップから復旧した・一部失われた可能性・途中の練習を捨てた・設定を初期値で動かす・学習記録の警告 | Must | 読込の結果 | 通知の一覧(画面で1回見せる) |
| R3 | 未完了セッションの再開 / 終了して新しく始める(回答済みの記録は残す)。残りの問題が今の単語データ・使えるモードで表示できないときは再開させない | Must | 利用者の選択 | 出題中 / ホーム(保存済み) |
| R4 | 練習の開始: 練習ごとの選択(自動ミックス・手動モード・問題数・苦手のみ・フラッシュ表示秒数)で出題を選び、セッションを作って保存する | Must | 練習の選択 | 出題中 / 0語のときは理由つきでホームのまま |
| R5 | 回答: 判定 → 記録 → 保存。保存できたら判定画面へ、できなければ判定画面で「保存失敗・再保存」 | Must | 入力文字列 | 判定(正誤・正しい綴り・差分・状態の変化・保存の成否) |
| R6 | 再保存: 保存に失敗した同じ内容を保存し直す。成功するまで次へ進めない | Must | 操作 | 判定画面(保存済み) |
| R7 | 次へ: 次の問題(再練習を含む)か、完了なら結果画面 | Must | 操作 | 出題中 / 結果 |
| R8 | 練習をやめる: 出題中に「再開の選択」へ戻る(セッションは保存済み。何も書かない) | Must | 操作 | 再開の選択 |
| R9 | 結果画面の集計 | Must | 完了したセッション | SessionSummary |
| R10 | 両方破損: 確認後にだけ新しい記録で開始。「終了」なら何も書かない | Must | 利用者の選択 | ホーム / 終了 |
| R11 | 新しすぎる版・読めない(ロック等)・単語データ不正: 保存も練習もせず、理由を示して終了のみ(読めないは「もう一度読む」も可) | Must | 読込の結果 | 終了のみ / 再読込 |

## 4. 非機能要件
- Reliability: 保存に失敗した回答は失われず、二重に記録されない(SessionManager の約束: Answer を同じ問題でもう一度呼ばない)
- Reliability: 進行役は許されない操作(出題中でないのに回答など)を受けたら状態を変えず例外にする(画面のバグを早く見つける)
- Compatibility: Schema 変更なし。progress.json・settings.json の形は変えない
- Maintainability: Windows 非依存。時刻は TimeProvider、乱数・セッションIDは外から受け取る
- Security / Privacy: 通知の文言にファイルのパスや誤答入力を含めない(Persistence の約束を引き継ぐ)
- Performance: 1回答の処理(判定・記録・保存)は 5,000語の記録でも画面が止まって見えない程度(目安 200ms 以内、Persistence の既存の保存時間に依存)
- スレッド: 進行役は1スレッドから呼ぶ前提(WPF の UI スレッド)。スレッドセーフにしない

## 5. 受入条件
- [ ] 初回起動(ファイルなし)→ ホーム。練習を始めて全問答え、結果画面まで進める
- [ ] 1問答えるごとに progress.json に記録とセッションが保存されている
- [ ] 途中で進行役を作り直す(= 再起動)と「再開の選択」になり、再開すると次の問題から続く。回答済みの記録は二重にならない
- [ ] 「終了して新しく始める」で記録は残り、セッションだけ消える
- [ ] 保存に失敗すると判定画面で「保存失敗」になり、次へ進めない。再保存に成功すると次へ進める。記録は1回分だけ
- [ ] 保存失敗のまま進行役を作り直すと、最後に保存できた時点から再開できる(失敗した回答は記録されていない)
- [ ] 主ファイル破損・バックアップ正常 → 復旧の通知を出してホーム(または再開の選択)
- [ ] 両方破損 → 選択画面。「終了」では何も書かれない。「新しい記録で開始」で壊れたファイルが退避されホームへ
- [ ] 新しすぎる版・読めない・単語データ不正 → 終了のみ(読めないは再読込可)。どのファイルも書き換えない
- [ ] 選べる単語が0語 → 理由つきでホームのまま、セッションを作らない
- [ ] 残りの問題が単語データから消えた・表示できないセッション → 再開は選べず、「終了して新しく始める」で記録を残してホームへ
- [ ] 保存先が絶対パスでない・単語データが壊れている(JSON・版・検査エラー)→ 例外で落ちず終了のみ
- [ ] 再練習を含むセッションの結果集計が、通常問題の正答数・誤答単語・再練習の結果・苦手状態の変化を正しく返す。再開をはさんでも同じ
- [ ] `dotnet build -warnaserror` と `dotnet test` が全件通る(Linux。Windows は CI)
