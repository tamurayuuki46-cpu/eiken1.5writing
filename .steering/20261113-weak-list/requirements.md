# requirements.md — 苦手一覧・学習状況

## 1. 目的
- なぜやるか: 苦手単語が記録されても、利用者がそれを見て「どこを間違えるか」「克服まであと何回か」を確かめる手段が無い(MVP Must 9「苦手単語一覧」、v1.0 11.3・11.4・16.1)。
- 終わったときの状態(Outcome): ホームで単語の状態ごとの語数が分かり、苦手一覧で苦手・克服済みの単語の誤答回数・モード別正答率・最後の誤答・克服状況を見て、そこから苦手のみの練習を始められる。

## 2. 範囲
- やること:
  - Core: 苦手一覧の行を作る `WeakWordList`、学習状況の語数 `StudyStatus`
  - Flow: ホームに学習状況、苦手一覧の画面(並べ替え・苦手だけに絞る・苦手のみ練習・ホームへ戻る)
- やらないこと:
  - WPF の画面(次のタスク)
  - 単語ごとの詳細画面、学習記録の編集・削除
  - モード別の全体正答率・今日の回答数・再確認の件数のホーム表示(今回は状態ごとの語数だけ。ユーザー決定)
  - 苦手度・最後の誤答以外の並べ替え(ユーザー決定)
  - 練習設定の保存(別タスク)

## 3. 機能要件
| # | 内容 | 優先度 | 入力 | 出力 |
|---|---|---|---|---|
| R1 | 学習状況: 単語データの語のうち 未出題 / 通常 / 苦手 / 克服済み の語数、克服済みのうち再確認待ちの語数 | Must | 単語データ・学習記録・今日 | StudyStatus |
| R2 | 苦手一覧: 状態が苦手・克服済みの単語を1行ずつ。単語・通常問題の誤答回数・モード別正答率(未出題は「未学習」)・最後の誤答(入力と日時)・学習状態・克服状況 | Must | 学習記録・単語データ・設定・今の時刻 | 行の一覧 |
| R3 | 克服状況: 苦手なら「克服まで あと n 回(連続正答 k / 必要回数)」と今日すでに対象正答したか、克服済みなら次回の再確認日と再確認待ちか | Must | 同上 | 行の項目 |
| R4 | 並べ替え: 苦手度の順(既定)/ 最後の誤答が新しい順 | Must | 並べ方 | 並んだ一覧 |

## 4. 非機能要件
- Performance: 5,000語の記録で一覧を作るのが体感で止まらない(目安 100ms 以内。v1.1 16.3「苦手一覧: 円滑な操作」)
- Maintainability: 学習ルールの値(必要回数・苦手度の点数)は LearningSettings から取る。苦手度は既存の WeakWordScorer を使い、同じ計算を2か所に書かない
- Privacy: 最後の誤答入力は画面に出すためのもの。画面の状態を丸ごとログに出さない約束(Flow)を引き継ぐ
- Compatibility: Schema 変更なし

## 5. 受入条件
- [ ] 初回(記録なし)の学習状況は 未出題 = 単語データの語数、それ以外 0
- [ ] 練習で苦手になった単語が一覧に出て、誤答回数・モード別正答率・最後の誤答が記録どおり。未出題のモードは「未学習」(null)
- [ ] 苦手の克服状況が「あと n 回」を設定の必要回数から出す(必要回数を変えた設定でも正しい)
- [ ] 克服済みの単語に次回の再確認日が出て、期限が来ていれば再確認待ちになる
- [ ] 苦手度の順は WeakWordScorer.Order と同じ並び。克服済みはその後ろ(再確認日の早い順)
- [ ] 最後の誤答が新しい順で並ぶ(誤答の無い単語は最後)
- [ ] 「苦手だけ」で克服済みが消える
- [ ] ホーム → 苦手一覧 → 苦手のみ練習 → 結果 → ホーム と進め、ホームの学習状況が練習の結果を反映している
- [ ] 苦手が0語のとき一覧から苦手のみ練習を押すと、理由つきで一覧のまま(何も保存しない)
- [ ] 受け付けない操作(一覧以外での並べ替えなど)は例外で状態が変わらない
- [ ] `dotnet build -warnaserror` と `dotnet test` が全件通る
