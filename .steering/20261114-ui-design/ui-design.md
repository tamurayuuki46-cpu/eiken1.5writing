## 1. 画面ごとのレイアウト

共通: 上から「ウィンドウのタイトル」→(通知)→ 内容。内容は中央にまとめ、最大幅を決めて左右の余白で広さの違いを吸収する(6章)。

| 画面 | 構成(上から) | 主ボタン(初期フォーカス) | モック |
|---|---|---|---|
| ホーム | 学習状況のカード5枚(苦手を強調)→「今日の練習」→ 練習設定の1行(問題数・出題・苦手のみ)→「始める」→ キーの案内・苦手一覧・設定 | 始める | AB 1行目 |
| 出題 | 進捗バー(上端)→ モード名・n / 合計 →(再練習なら説明)→ 問題(日本語・穴あき+文字数)→ 入力欄 → キーの案内 | 入力欄 | AB 1行目 |
| 判定 | n / 合計・保存の状態 →(保存失敗の警告)→ 正誤 → 正しいスペル(誤りの文字を強調)→ 差分の文章 → あなたの入力 → 記録の変化 → 次へ | 次へ(保存失敗中は「もう一度保存」)| AB 1・2行目 |
| 結果 | 見出しと「通常問題 n / m 正解」→ 3枚のカード(間違えた単語 / 再練習の結果 / 苦手状態の変化)→ ホームへ | ホームへ | AB 2行目 |
| 再開の選択 | (通知)→ 見出し → 開始日時・回答済み n / m → 続きから → 終了して新しく始める → 説明 | 続きから(再開できないときは「終了して新しく始める」だけ)| AB 3行目 |

| 終了のみ(Fatal)| 見出し → 理由 → (読込不可のときだけ)再読込 / 終了 | 再読込があればそれ、なければ終了 | 未作成(両方破損と同じ型)|

### 文言の方針
- 画面の文言は Flow が持つもの(保存失敗・開始失敗・通知など)をそのまま出す
- 差分の文章は Core の `SpellingDiffService.Describe` を使う(5章)
- Flow・Core が持たない文言(0語の理由、記録の変化、ボタン名)は ViewModel 側の文言表(ScreenText)で作る。**判断は Core・Flow、値の言い換えだけを表示側に置く**

## 2. 色(トークン)

コントラストは文字 4.5:1 以上(WCAG AA)を目安に選んだ。色だけで区別せず、記号と文字を必ず併記する(UX-11)。

| 名前 | 値 | 用途 |
|---|---|---|
| Background | #F7F7F5 | ウィンドウの地 |
| Surface | #FFFFFF | カード・入力欄 |
| Border | #E2E2DE | カードの枠・区切り |
| BorderStrong | #C9C9C4 | 入力欄・選択ボタンの枠 |
| Text | #1B1B1F | 本文 |
| TextSub | #55575E | 補足・キーの案内 |
| Accent | #2F5BD3 | 主ボタン・フォーカス・進捗・**正解** |
| AccentDark | #1F3F9E | 主ボタンの押下・正解の文字 |
| AccentSoft | #E8EEFB | 正解の「記録の変化」・情報の通知の地 |
| Mistake | #B54708 | **不正解**・苦手の強調 |
| MistakeText | #8A3505 | 誤りの文字・苦手の文字 |
| MistakeSoft | #FDE3CF / #FDF0E6 | 誤りの文字の地 / 不正解の「記録の変化」の地 |
| Danger | #B42318 | 保存失敗の警告・破壊的な操作 |
| DangerSoft | #FEECEB | 保存失敗の警告の地 |
| Saved | #3B5E3F | 「保存しました」(記号つき)|
| Disabled | #EDEDEA 地 / #6B6D73 文字 | 無効のボタン |

正解を青、不正解を橙にしたのは、赤と緑の見分けにくさを避けるため(色覚の違いへの配慮)。

## 3. 文字

| 用途 | WPF のフォント | 大きさ(px 相当)| 太さ |
|---|---|---|---|
| 本文・ボタン | Yu Gothic UI(英数は Segoe UI)| 15 / ボタン 18〜22 | 標準 / 太字 |
| 見出し | 同上 | 24〜30 | 太字 |
| 問題(日本語)| 同上 | 34 | 太字 |
| 英単語(問題・正しいスペル・入力欄)| Cascadia Mono(無ければ Consolas)| 入力 34 / 正しいスペル 52 / 穴あき 46 | 太字(入力は標準)|
| 補足・キーの案内 | Yu Gothic UI | 13〜14 | 標準 |

- モックは Web フォント(Noto Sans JP・JetBrains Mono)で描いている。WPF では上の Windows 標準フォントに置き換える(追加の配布は不要)
- 英単語は等幅にする。1文字ずつの位置が揃い、差分の位置が分かりやすい

## 5. 正誤・差分の表示

Core の `SpellingDiff`(種類・正解側の位置・入力側の位置・正しい文字・入力した文字)をそのまま使う。

**文章の正本は Core の `SpellingDiffService.Describe`**(H2、2026-11-14。表示側で文章を作り直さない)。

| 種類 | 正しいスペル側 | 入力側 | 文章(Describe)|
|---|---|---|---|
| 不足 Missing | その文字を MistakeSoft の地+下線で強調 | — | 「6文字目のmが不足しています」 |
| 余分 Extra | 強調なし | 余分な文字を取り消し線+MistakeSoft の地 | 「入力の5文字目のlは不要です」 |
| 置換 Wrong | その文字を強調 | — | 「4文字目はeではなくaです」 |
| 入れ替わり | Wrong が2つ並ぶ(Core の決定)。両方を強調 | — | 置換の文章を2行 |

- 「あなたの入力」と入力側の強調は、判定と同じく **前後の空白を除き小文字にした文字列**(`SpellingJudge.Normalize` の結果)で表示する。`InputPosition` はその文字列の位置なので、そのまま表示するとずれるため(レビュー P1-2)
- 「あなたの入力」は画面にだけ出し、ログ・例外・`ToString`・スクリーンリーダー用の名前には出さない(H4、DECISIONS「進行役 Flow」)
- 誤りが多いとき: 文章は最初の3件(`SpellingDiff` の件数。入れ替わりは2件)まで出し、残りは「ほか n か所」とまとめる(強調はすべて)
- 正解のとき: 正しいスペルだけを強調なしで出す
- 長い単語: 正しいスペルの文字の大きさを、窓の幅に収まるまで段階的に下げる(52 → 40 → 32)。折り返さない

## 6. 画面サイズへの対応

- 窓の既定の大きさ: 1000×680。最小: 800×560。ただし画面の作業領域(タスクバーを除く)より大きくならないよう、既定・最小とも作業領域で頭打ちにする(1920×1080 を 200% 表示にすると高さが 540 しかないため。H3)
- 内容の最大幅: 760。広い窓では左右の余白が増える
- 高さが足りないときは内容を縦にスクロールする(主ボタンが隠れないよう、判定と結果は主ボタンを下に固定する)
- Windows の拡大表示(125%・150%・200%)と高 DPI で崩れないこと(WPF の論理単位で作る)
- 結果のカード3枚は、内容の幅が 640 未満なら縦に並べる

## 7. エラー・状態の表示

| 状況 | 表示 | 位置 |
|---|---|---|
| 保存失敗(判定)| 警告の帯+「もう一度保存」+無効の「次へ(保存後に押せます)」| 判定画面の上部 |
| 練習の開始に失敗・0語 | 警告の帯(開始失敗)/ 情報の帯(0語の理由)| ホーム・苦手一覧の練習設定の上 |
| 起動時の通知 | 情報の帯・閉じるボタン | 最初の画面の上部 |
| 両方破損 | 専用の画面+確認ダイアログ | 全面 |
| 終了のみ | 専用の画面 | 全面 |
| 想定外の例外 | 内容を伏せた文言のダイアログを出し、**アプリを終了する**(Flow の状態が壊れている可能性があるため、保存も画面の続行もしない。H1)| 全面 |
| 保存できた | 「保存しました」(記号つき)| 判定画面の右上 |
