# 設計

## Core(進行と採点の分離)
- `PracticeSession.Skips`(`SessionSkip(QuestionIndex, SkippedAt)` の配列、スキップした順)を最小の台帳にする。採点は従来どおり `Answers`(採点した順)
- 採点の順は台帳から一意に決まる: スキップしなかった通常問題(番号順)→ スキップした通常問題(スキップ順 = 後回し)→ 再練習(番号順)。
  `Answers[k]` はこの順の k 番目の問題への採点。v1 のセッション(Skips なし)では従来の位置どおり(再採点・並べ替えなし)
- 今の問題 = この順の `Answers.Length` 番目。段階(通常 / 後回し / 再練習)も同じ順から求める
- スキップできるのは「通常の段階で、まだスキップしていない通常問題」だけ(後回し・再練習では不可。通常問題の単語は重複しないので単語ごとの上限1回も同時に守られる)
- answerId は元の通常枠の番号のまま(後回しで答えても同じ ID)。再練習はすべての通常枠を採点し終えたときに足す
- SessionValidator: 台帳の番号が通常問題の範囲・重複なし・スキップ順(昇順)・スキップ時点で前の通常問題を処理済み、反映済み ID が採点済みの枠と一致、Replay で再練習の列が一致

## Flow(同じ候補の再保存)
- `PracticeFlow.Skip()`: 今の問題がスキップ可能なときだけ。候補文書を一度だけ作り(時刻はこのとき1回)、保存
  - 成功: 文書を候補に置き換え、次の問題へ
  - 失敗: 文書は変えず候補を保持。画面は同じ問題で `SkipSaveFailure` を持つ。回答・スキップ・中断は拒否、`RetrySave` だけ受け付ける
- `RetrySave()` は保持した候補をそのまま保存し直す(スキップを再実行しない)
- QuestionScreen に `Phase`(通常 / 後回し / 再練習)と `CanSkip` を持たせる。WPF はそれを表示するだけ

## Persistence(Schema v2)
- `ProgressDocument.CurrentSchemaVersion = 2`。v1 も読む(Skips が無い = 空)。保存は常に v2(古いアプリは NewerVersion で書き込まない)
- 起動・読込だけでは書かない(従来どおり)
- 最初の保存の前に、主ファイルが v1 なら主と(あれば)bak の原本バイトを保護する: `progress.v1-protected.main.json` / `.bak.json`
  - `.partial` に書いて読み戻しでバイト一致を確かめてから完成名へ移動(完成名がある = 検証済み)
  - 同じ役割の完成コピー(基本名と -2, -3 …)のどれかが一致すれば再利用。どれとも一致しなければ次の別名に新しく保護して続ける(既存は上書きしない)
    - レビュー(3体の P1)とユーザー決定(2026-11-15)で「不一致なら停止」から変更。止めると bak からの復旧後・旧版に戻した後に保存できなくなるため
  - 保護に失敗したら保存しない

## 戻し方(database.md「Schema 変更」)
- 旧版のアプリに戻すときは、旧版を起動する前に `progress.v1-protected.main.json` を `progress.json` に置き直す(v2 で記録した分は失われる)
- 自動のダウングレードはしない。旧版は v2 を NewerVersion として読まず、上書きもしない
