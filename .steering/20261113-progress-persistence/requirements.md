## 1. 目的
- なぜやるか: 学習記録と設定を、アプリを閉じても失わず、保存中の電源断やファイル破損でも壊さずに残す。Core Value の「克服するまで繰り返す」は、記録が次回に残って初めて成り立つ
- 終わったときの状態(Outcome): 指定したフォルダに progress.json / settings.json を安全に保存・読込でき、主ファイルが壊れていればバックアップから自動で復旧し、両方壊れていれば勝手に初期化せず状態を知らせる

## 2. 範囲
- やること:
  - progress.json の形(schemaVersion・wordSetVersion・sourceVersion・学習記録)と、文字列との変換
  - 読み込んだ学習記録の検査(ProgressValidator。⑥ レビューからの引き継ぎ)
  - 安全な保存の手順(一時ファイル → 読み戻して検証 → 既存を .bak.json に退避して置き換え)(v1.0 13.7)
  - 読込と復旧(主ファイル正常 / 初回 / バックアップから自動復旧 / 両方破損)(v1.0 13.4・13.5)
  - settings.json の保存・読込・破損時の復旧(不正な設定は保存しない)(v1.2 7〜9章)
  - 誤答入力の長さの上限(⑥ レビューからの引き継ぎ)
- やらないこと:
  - セッションの進行状態(次のタスクで progress.json に任意項目として追加)
  - 画面(復旧の通知・「新しい記録で開始 / 終了」の選択・再保存ボタン)— WPF 側
  - %APPDATA% の場所を決めること — WPF 側が保存先フォルダを渡す
  - 手動バックアップ・エクスポート/インポート(v1.0 13.6、v0.1 では作らない)
  - 複数のアプリを同時に起動したときの排他

## 3. 機能要件
| # | 内容 | 優先度 | 入力 | 出力 |
|---|---|---|---|---|
| R1 | progress.json の形と変換。壊れた JSON・型違い・明示的な null・新しすぎる schemaVersion は InvalidDataException | Must | 学習記録・単語データの版 / JSON 文字列 | JSON 文字列 / 学習記録 |
| R2 | 学習記録の検査(design.md 4章の項目) | Must | 学習記録 | 問題の一覧(重大 / 警告) |
| R3 | 安全な保存。途中で失敗しても主ファイルと直前のバックアップが壊れない | Must | 保存先・内容 | 成功 / 失敗(理由) |
| R4 | 読込と復旧: 正常 / 初回(ファイルなし)/ 主ファイル破損でバックアップから復旧(壊れたファイルは別名で残す)/ 両方破損(何も変えずに知らせる) | Must | 保存先 | 学習記録と読込結果 |
| R5 | 両方破損のとき、利用者の確認後にだけ新しい記録で始める。壊れたファイルは残す | Must | 確認の操作 | 空の学習記録 |
| R6 | settings.json の保存。SettingsValidator で不正なら保存せず理由を返す | Must | 設定 | 成功 / 不正(理由) |
| R7 | settings.json の読込。壊れていればバックアップ、それも駄目なら初期値で動かし理由を返す。学習記録には触れない | Must | 保存先 | 設定と読込結果 |
| R8 | 誤答入力は上限の文字数で切り詰めて記録する | Should | 回答 | 切り詰めた入力 |

## 4. 非機能要件
- Reliability: 保存中に処理が止まっても、主ファイルか直前のバックアップのどちらかは必ず正常に読める
- Compatibility: 知らない項目は無視し、無い項目は初期値(セッションを後から足しても schemaVersion を上げずに済む)
- Maintainability: Windows 非依存(net10.0)。本物のファイルでテストできる
- Security: テストは一時フォルダだけを使い、実際の %APPDATA% には触れない

## 5. 受入条件
- [ ] 学習記録を保存して読み直すと、同じ内容(単語・モード別記録・日付・反映済み answerId)に戻る
- [ ] 2回目以降の保存で、前回の内容が progress.bak.json に残る
- [ ] 一時ファイルへの書き込み・置き換えの途中で失敗させても、主ファイルとバックアップは前の正常な内容のまま
- [ ] 主ファイルを壊すとバックアップから復旧し、「復旧した」と分かる結果を返す。壊れたファイルは別名で残る
- [ ] 両方壊すと、どのファイルも変えずに「両方破損」を返す。確認後に新しく始めても壊れたファイルは残る
- [ ] ファイルが1つも無ければ「初回」として空の学習記録を返す
- [ ] 不正な設定は保存されず、理由が返る。壊れた settings.json では初期値で動き、progress.json は変わらない
- [ ] 検査で重大な問題がある学習記録は「壊れている」と同じ扱いになる
- [ ] `dotnet build -warnaserror` と `dotnet test` が全件通る
