## 1. 目的
- なぜやるか: 学習ロジック(Core)・保存(Persistence)・進行役(Flow)はそろったが、画面が無いため Windows 実機で
  「起動 → 出題 → 保存 → 再起動 → 復元」(CLAUDE.md 10章の完了条件)を確かめられない。
- 終わったときの状態(Outcome): 利用者が Windows でアプリを起動し、ホームから練習を始め、日本語・穴あきの問題に
  キーボードだけで答え、判定(正誤・差分・記録の変化・保存の状態)を見て結果画面まで進める。途中でアプリを閉じても、
  次の起動で再開を選べる。破損・保存失敗・読めないときも、承認済みの UX・UI 設計どおりの画面が出て、連打や想定外の例外で
  既定の例外ダイアログが出ない。見た目は採用案 A+B(UI 設計)の色・文字・部品の状態に沿う。

## 2. 範囲
- やること:
  - 新しいプロジェクト `EikenSpelling.Wpf`(net10.0-windows、WPF)と、ViewModel の新しいプロジェクト
    `EikenSpelling.Presentation`(net10.0、Windows 非依存)、そのテスト `EikenSpelling.Presentation.Tests`
  - Flow の `HomeScreen` に問題数の選択肢 `QuestionCountChoices` を足す(既存の振る舞いは変えない)
  - Core の `SpellingJudge` に「空か」の判定 `IsBlank` を足す(`Normalize` の結果が空。既存の振る舞いは変えない。レビュー P0-1)
  - 起動: 二重起動の防止 → 保存先の決定 → 単語データの読み込み → Flow の起動 → 最初の画面の表示
  - 表示する画面: ホーム / 再開の選択 / 出題 / 判定 / 結果 / 両方破損 / 終了のみ、起動時の通知、保存失敗時の再保存
  - ホームの練習設定(問題数・自動ミックスか手動モードか・苦手のみ)と学習状況のカード5枚
  - UI 設計の色・文字・部品の状態(通常・フォーカス・押下・無効)・差分の強調・窓の大きさ
  - 仮の単語データ(自作の訳で十数語)の同梱
  - 手書きのファイルログ(保存・読込の失敗と想定外の例外)
- やらないこと:
  - 音声モード(System.Speech)とフラッシュモード(表示秒数の計時)。今回は端末のモードを 日本語・穴あき に絞る(次のタスク)
  - 苦手一覧の画面・設定画面と、ホームからの入口(次のタスク。UX-14・UX-15 もそこで扱う)
  - 学習ロジック・画面遷移の判断を画面側に書くこと(Flow と Core の責務。WPF・Presentation は写すだけ)
  - 正式な単語データ(約5,000語)と日本語訳の辞書(U2。ライセンス確認待ち)
  - アニメーション・アイコンの作り込み(UI 設計の記号は簡単な図形で描く)、インストーラ・配布
  - 手動バックアップ・エクスポート(v0.1 対象外)
  - 上の2点(`HomeScreen.QuestionCountChoices`・`SpellingJudge.IsBlank`)以外の Flow・Persistence・Core の変更(必要になったら止めて報告する)
  - NuGet パッケージの追加(今回は追加しない)

## 4. 非機能要件
- 依存の向き: `Wpf → Presentation → Flow → Persistence → Core`(`Presentation → Core`・`Wpf → Core` も可)。Presentation は Windows 専用のアセンブリ(WindowsBase・PresentationCore・PresentationFramework)を参照しない。
  `System.Windows.Input.ICommand` は net10.0 の System.ObjectModel にあり Linux でも使えるので使ってよい
- Presentation は net10.0。テストは Linux(クラウド・CI の ubuntu-latest)でも動く。時間に関わる処理(Enter を無視する時間)は `TimeProvider` で測り、固定時間の待ちを使わずにテストする
- Linux の CI でソリューション全体の `dotnet build -warnaserror` が通る(WPF のプロジェクトも含めて)
- 応答: 1問の回答から判定画面の表示までは、保存の再試行が無ければ体感で待たない程度(同期で保存する。design.md 6章)
- 文言とログを分ける(DECISIONS「進行役 Flow」)。判断を伴う文言は Flow・Core、値の言い換えだけを Presentation に置く
- 実際の `%APPDATA%` をテストで使わない(testing.md)
- NuGet の追加なし。警告 0

## 5. 受入条件
- [ ] R1: アプリを起動したまま、もう一度起動すると、最初のウィンドウが前に出て、2つ目のプロセスが終わる(手動・Windows)
- [ ] R2: `--data-dir <一時フォルダ>` で起動すると、そのフォルダに progress.json ができ、`%APPDATA%\EikenSpelling` は変わらない(手動)。相対パスを渡すと「保存先のフォルダが正しくありません。」の画面になる(単体・手動)
- [ ] R3: words.json を消す / 壊すと「単語データを読み込めません。」の画面になり、何も書かれない(単体・手動)
- [ ] R4・R6〜R8・R11・R16: 初回起動 → ホーム → 5問で始める → 日本語・穴あきの問題に答える → 誤答で差分と記録の変化が出る → 再練習(印と説明)→ 結果 → ホームで学習状況が増えている(単体 + 手動)
- [ ] 再起動・復元: 練習の途中でウィンドウを閉じる → 再起動 → 再開の選択 → 続きから → 前の続きの番号から出る(手動。CLAUDE.md 10章)
- [ ] R5: 起動時の通知と StartFresh 後の通知が、閉じるまで残る(単体)
- [ ] R9: `""`・`"   "`・`"\t"` で回答しても画面が変わらず、ファイルも書かれない(単体)
- [ ] R10: IME をオンにしたまま回答欄で打っても英字が入る / 確定前の文字が回答に入らない(手動)
- [ ] R11: 差分の文章が Core の `Describe` と一致する。4件以上で「ほか n か所」。先頭に空白・大文字のある入力(`" Recieve"`・`"ACCOMODATE"`)で入力側の強調がずれない(単体)
- [ ] R12: 画面が変わってから 0.29 秒のコマンドは無視、0.30 秒以降は受け付ける(判定 → 結果 → ホームの素早い連続操作を含む。単体)。出題で Enter を押したままでも判定にとどまる(手動)
- [ ] R11・R13: 保存失敗 → 再保存の成功の後も「n / 合計」と「あなたの入力」が出ている(単体)。フォーカスが「次へ」に移る(手動)
- [ ] R25: 保存失敗中に閉じると確認が出る / それ以外・「終了」・想定外の例外での終了では確認が出ない(単体 + 手動)
- [ ] R10・R21: 貼り付けた改行が除かれる、正誤・差分が色だけで伝えていない、ナレーターで主な部品の名前が読まれる(手動)
- [ ] R13: progress.json を別のアプリで開いて書けないようにして回答 → 警告の帯・「もう一度保存」・無効の「次へ」→ ロックを外して Enter で再保存 → 次へ(単体は IFileOperations の差し替え + 手動)。ログに Diagnostic と sessionId が出て、パス・入力が無い
- [ ] R14: やめる → 確認で「いいえ」なら出題のまま、「はい」で再開の選択(単体)。Esc でも同じで、「いいえ」の後そのまま打てる(手動)
- [ ] R15: 再開の選択で「終了して新しく始める」→ ホーム / 再開できないときは「続きから」が無い(単体)
- [ ] R17: progress.json と progress.bak.json を両方壊して起動 → 両方破損の画面 → 「終了」で何も書かれない / 確認で「いいえ」なら何も書かれない / 「はい」でホーム(単体 + 手動)
- [ ] R18: 新しすぎる版の progress.json で起動すると「終了」だけ、ロックで読めないときは「再読込」も出る(単体)
- [ ] R6・R7: 開始の保存に失敗すると警告の帯が出る / 保存済みの手動モードが音声・フラッシュなら選択肢に出て、始めると使えない理由が出る(単体)
- [ ] R15: 「終了して新しく始める」の保存に失敗すると Message が出て、再開の選択のまま(単体)
- [ ] R19: Home・Question・Feedback・Result で同じ操作を2回続けて実行しても、2回目は何もしない・例外が出ない(単体)
- [ ] R20〜R22: 各画面の初期フォーカス、Tab の順、フォーカスの輪、最小の窓・200% 表示で主ボタンが隠れない(手動。画面ごとの確認表は tasklist.md)
- [ ] R24: 想定外の例外を起こしても既定の例外ダイアログが出ず、ログに残り、終了する(手動。開発用の仕組みは作らず、確認方法は tasklist に書く)
- [ ] 既存データが壊れない: 起動しただけ・ホームを開いただけでは progress.json・settings.json が書かれない(単体)
- [ ] `dotnet build -warnaserror` が警告 0、`dotnet test` が全件通過(既存 960 件 + Core・Flow・Presentation の新しいテスト)。CI の ubuntu-latest と windows-latest の両方で通る
