# Windows 実機の手動確認(M1〜M14)

- 対象: ブランチ `feature/word-data`(骨組み + 4,924 語の単語データ)
- 本物の学習記録(`%APPDATA%\EikenSpelling`)を汚さないよう、**確認用の保存先**を使う
- コマンドはすべて PowerShell(Windows ターミナル)で実行する。結果は下の表の「結果」に ○ / × とメモを書く

## 準備(1回だけ)

```powershell
cd C:\Users\yuuki\Documents\eiken1.5writing
dotnet build src\EikenSpelling.Wpf
$exe  = "C:\Users\yuuki\Documents\eiken1.5writing\src\EikenSpelling.Wpf\bin\Debug\net10.0-windows\EikenSpelling.exe"
$data = "$env:TEMP\eiken-check"
New-Item -ItemType Directory -Force $data | Out-Null
```

起動するとき(以下「確認用に起動」):

```powershell
& $exe --data-dir $data
```

まっさらからやり直すとき(確認用の保存先を空にする):

```powershell
Remove-Item "$data\*" -Force
```

## 確認の手順

### M1 通しの練習・閉じて再開
1. 確認用に起動 → ホームが出る(学習状況: 未出題 4,924 など)
2. 問題数を 5 にして(既定は 10)「始める」(Enter でも可)→ 出題 → 英単語を打って Enter → 判定 → Enter で次へ を数問
3. 途中(3問目くらい)で窓の × で閉じる
4. もう一度確認用に起動 → 「前回の練習が途中です」(回答済み 2 / 5 など)→「続きから」→ 続きの番号から出る → 最後まで → 結果 → ホームへ

### M2 二重起動
1. 確認用に起動したまま、もう一度 `& $exe --data-dir $data` を実行
2. 2つ目の窓は出ず、最初の窓が前に出る(最小化していても戻る)

### M3 保存先の差し替え
1. M1 の後、`Get-ChildItem $data` に progress.json があること
2. `Test-Path "$env:APPDATA\EikenSpelling\progress.json"` が(以前に本番で使っていなければ)False のまま

### M4 保存失敗 → もう一度保存
1. 確認用に起動して練習を始め、出題画面にしておく
2. 別の PowerShell で progress.json をロックする:
   ```powershell
   $f = [IO.File]::Open("$env:TEMP\eiken-check\progress.json", 'Open', 'Read', 'None')
   ```
3. アプリで回答 → 判定画面の上に赤い「保存できませんでした」、「もう一度保存」と無効の「次へ(保存後に押せます)」
4. Enter → まだ失敗する(ロック中)
5. ロックを外す: `$f.Close()`
6. Enter(もう一度保存)→「✓ 保存しました」になり、フォーカスが「次へ」に移る → Enter で次の問題へ

### M5 破損からの復旧・両方破損
1. アプリを閉じる。progress.json だけ壊す: `Set-Content "$data\progress.json" "{ broken"`
2. 確認用に起動 → 上に「バックアップから復旧しました」の帯。画面を移っても閉じるまで残る。「閉じる」で消える
3. アプリを閉じる。両方壊す:
   ```powershell
   Set-Content "$data\progress.json" "{ broken"
   Set-Content "$data\progress.bak.json" "{ broken"
   ```
4. 確認用に起動 →「学習記録を読み込めませんでした」→「新しい記録で始める」→ 確認で「いいえ」→ 何も変わらない(`Get-ChildItem $data` で壊れたファイルがそのまま)
5. もう一度「新しい記録で始める」→「はい」→ ホーム。壊れたファイルは `*.corrupt-*.json` の名前で残っている

### M6 IME・貼り付け
1. 日本語入力をオン(ひらがな)にしたまま、出題画面の回答欄で文字を打つ → 英字が入る
2. メモ帳で「ab(改行)c」を書いてコピーし、回答欄に貼り付け → 改行が消えて「abc」になる

### M7 初期フォーカス・Tab
各画面で、何も触らずに Enter を押したときに押されるボタンと、フォーカスの輪(青い枠)を見る
- ホーム: 始める / 出題: 回答欄 / 判定: 次へ(保存失敗中は もう一度保存)/ 結果: ホームへ / 再開の選択: 続きから / 両方破損: 終了 / 終了のみ: 再読込(あれば)
- Tab で順に移り、輪がいつも見えること

### M8 押しっぱなし・Esc
1. 出題画面で Enter を押したままにする → 判定画面にとどまる(次の問題へ飛ばない)
2. 出題画面で Esc を押したままにする → 確認が1回だけ出る
3. 「やめますか?」で「いいえ」→ そのまま文字を打てる(回答欄にフォーカスが戻る)

### M9 素早い連続操作
1. 出題画面で「回答」ボタンをダブルクリック → 判定画面にとどまる
2. どの画面も、出てから少し(約0.3秒)たてば普通に操作できる

### M10 通知を閉じた後のフォーカス
M5 の帯の「閉じる」を押した後、Enter でその画面の主なボタンが押される

### M11 窓の大きさ・拡大表示
1. 窓をいちばん小さくする → 主なボタン(始める・次へ・ホームへ)が隠れない(縦にスクロールできる)
2. 設定 → システム → ディスプレイ → 拡大/縮小 を 125% / 150% / 200% にして同じことを見る(終わったら元に戻す)

### M12 色だけに頼らない・ナレーター
1. 判定画面で「✓ 正解」「✕ 不正解」の記号と文字が出る。差分は文章(「4文字目は…」)でも出る
2. ナレーターを起動(Ctrl + Windows + Enter)→ 回答欄で「回答の入力欄」、判定画面で正誤が読まれる → もう一度 Ctrl + Windows + Enter で終了

### M13 閉じる前の確認
1. M4 の保存失敗中(ロック中)に窓の × → 「この回答はまだ保存できていません…閉じますか?」が出る。「いいえ」で閉じない
2. 保存できている状態で × → 確認なしで閉じる
3. 両方破損の画面の「終了」→ 確認なしで閉じる

### M14 想定外の例外
- 例外をわざと起こす仕組みは作っていないので、今回は確認できない(次のタスクで開発用の仕組みを入れるか判断)。
  ログの場所だけ見る: `Get-ChildItem "$env:LOCALAPPDATA\EikenSpelling\logs"`(M4 の保存失敗の行があるはず。中身にパス・入力した文字が無いこと)

### 単語データ(4,924 語)
- 何回か練習して、訳から綴りが一つに決まるか(意味が重なる語には「(b・3文字)」のような手がかり)、穴あきが妥当か、気になった語をメモする

## 見つかった不具合(2026-11-14)
- B1: ホームで問題数を 5 に選んで「始める」を押しても、出題は「1 / 10」(10問)になった。選択が練習に反映されていない可能性(ComboBox の SelectedItem と int の結び付け、または選択の操作の問題。要調査)
- B2: 画面が出た直後は、初期フォーカスはあるのにフォーカスの輪が見えない(WPF はキーボード操作の後にだけフォーカスの輪を出す既定の動き)。R20「フォーカスの位置が常に見える」に合わない
- B3(軽微): 起動直後に窓が前面に来ず、最初の Enter が窓の前面化に使われて効かなかった

- B5: 判定画面に移っても、ナレーターが正誤を読まない(フォーカスの移った「次へ, ボタン」だけ)。LiveSetting=Assertive を付けた TextBlock は新しく作られるだけで、読み上げの合図(LiveRegionChanged)が出ていないためと見られる(推測)。R/UX の「判定画面で正誤が読まれる」に合わない
- B4(要判断): 判定画面の正しいスペル・あなたの入力が UI Automation に1文字ずつの Text として出る(M12)

### 調べた結果と対応(2026-11-14)
- B1: **再現せず**。修正前のビルドで (a) マウスで 5 を選ぶ (b) 選択欄を開いて ↑ → Enter (c) Alt+N → ↑ → Enter の3通りとも「1 / 5」で始まった。コード(HomeViewModel → PracticeChoiceApplier → QuestionSelector)にも誤りは見つからない。既定の問題数は 10 で、手順書 M1 が「5 のまま」と書いていたため、前回は 5 を選べていなかった可能性が高い(推測)。手順書を「5 にして(既定は 10)」に直した。コードは変えていない
- B2: 原因は WPF の既定の動き(FocusVisualStyle はキーボード操作の後にしか描かない)。`FocusRing.Show`(Wpf/FocusRing.cs)を作り、キーボードフォーカスを持つ間は入力の種類にかかわらず装飾(Adorner)で同じ見た目の輪を描くようにした。ボタン・選択欄・チェックボックスのスタイルは FocusVisualStyle を null にして二重の輪を防ぐ。WPF 専用でテストのプロジェクトが無いため、実機で確認(M7 ○)
- B3: 起動時に `Show()` の後で `Activate()` を呼ぶようにした。修正前も前面に来ることがあり再現は不安定だったが、修正後は起動直後の最初の Enter が効いた(M13 の3)
