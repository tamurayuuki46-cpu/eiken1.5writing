## 1. 目的
- なぜやるか: 骨組みの単語データは仮の18語だけ。仕様 v1.1(採用済み)は NGSL・NAWL・BSL を統合した約5,000語を収録する。
- 終わったときの状態(Outcome): アプリに約5,000語が同梱され、日本語・穴あきのモードで出題できる。各語に出典・頻度順位・Tier・日本語訳・穴あき表示があり、
  データの検証レポートで重複・訳なし・不正文字・穴あきの不整合が 0 件と分かる。ライセンス(CC BY-SA 4.0)の出典表示がリポジトリにある。

## 2. 範囲
- やること:
  - 3リストの公式 CSV を取得してリポジトリに置く(出典・版・取得日・ライセンスを記録)
  - 統合: 表記の正規化、重複の統合(出典は配列)、頻度順位の保持、除外候補の抽出
  - 日本語訳: Claude が全語に短い訳(意味1〜2個)を自作する。同じ訳の語は日本語モード不可にして確認対象に(仕様 v1.1 6.1)
  - Tier(新規の出題順): Tier 1 = 英検準1級ライティングで使いやすい重要語(300〜800語)、Tier 2 = NAWL の残り・関連の高い BSL 語、Tier 3 = その他(仕様 v1.1 14章)
  - 穴あきの自動生成: ルールベース(二重子音・間違えやすい母音・黙字・-able/-ible・-ance/-ence など)。手動指定が優先(仕様 v1.1 5章)。Core に生成と検証を置く
  - 単語データを作る道具(リポジトリ内の小さなコンソール)と検証レポート
  - 5,000語での読込・出題の性能確認(読込 1 秒以内を目安。仕様 v1.1 16.3)
  - ライセンス文書と出典表示(リポジトリ。アプリ内の表示は次のタスク)
- やらないこと:
  - 音声モード・同音異義語の判定(音声のタスク。audioEligible は全語 true のまま)
  - 苦手一覧・設定画面(次のタスク)
  - 外部の辞書の利用(ユーザー決定で自作訳)
  - 判定画面の「苦手に登録」の判定の Core への移動(wpf-shell から送られた項目。別タスク)

## 3. 機能要件
| # | 内容 | 優先度 |
|---|---|---|
| D1 | 3リストの CSV を取得し `data/sources/` に置く。版・取得日・URL・ライセンスを `data/sources/SOURCES.md` に記録 | Must |
| D2 | 統合: 小文字・前後の空白を正規化し、同じ綴りを1件にまとめ、出典を配列で持つ。単語 ID は綴り(固定。取り込み順に依存しない) | Must |
| D3 | 頻度順位: NGSL の順位を優先し、NGSL に無い語は各リストの順位を後ろに並べる(design 4.2) | Must |
| D4 | 除外: スペル練習の意味が薄い語(6章 Q1)を除外リストに挙げ、理由をレポートに出す。「3文字以下はすべて除外」はしない(仕様 v1.1 2.3) | Must |
| D5 | 日本語訳: 除外しなかった全語に訳を付ける。訳が空の語は出さない(検証エラー)。同じ訳を持つ語は日本語モード不可にしてレポートに出す | Must |
| D6 | Tier: Tier 1 の語の一覧を作り、Tier 2・3 は規則で決める | Must |
| D7 | 穴あき: 全語に自動生成(手動指定があればそれ)。元の単語と同じ長さ・穴を埋めれば元に戻る・穴が1つ以上・全部は隠さない | Must |
| D8 | 検証レポート: 語数(リスト別・統合後)、重複、除外とその理由、訳なし、同じ訳、穴あきの生成方法の内訳、検証エラー 0 | Must |
| D9 | 既存の学習記録を壊さない: 仮データの18語は同じ ID で残る。単語データに無い記録は数えないだけ(既存の約束) | Must |
| D10 | 性能: 5,000語の読込・検証・出題の選択がテストで 1 秒以内(Windows 実機・CI の目安) | Should |
| D11 | 出典表示: `data/LICENSE-DATA.md` と README に、3リストの出典と CC BY-SA 4.0、単語データ(訳を含む)も CC BY-SA 4.0 で公開する旨 | Must |

## 4. 非機能要件
- Core は Windows 非依存のまま。穴あきの生成は Core(Domain)に置き、Linux でもテストする
- 単語データを作る道具はアプリに含めない(`tools/` に置く。テストから呼べる形)
- NuGet の追加なし(CSV は自前で読む)
- 学習ルールの値を道具に直接書かない(Tier の件数の目安などは道具の設定として1か所に)

## 5. 受入条件
- [ ] D1・D11: 3リストの CSV と出典・ライセンス文書がリポジトリにある
- [ ] D2〜D8: 道具で words.json と検証レポートを作り直せ、検証エラー 0(テスト)
- [ ] D5: 全語に訳があり、ユーザーが抜き取り(6章 Q3)で確認した
- [ ] D7: 穴あきの生成のテスト(ルールごと・同じ長さ・復元・穴が1つ以上・全部は隠さない・手動優先)
- [ ] D9: 仮データの18語の ID が新しいデータにもある(テスト)
- [ ] D10: 5,000語の読込から出題の選択まで 1 秒以内(テスト)
- [ ] アプリで5問の練習ができる(画面外の確認と、可能なら実機)
- [ ] `dotnet build -warnaserror` と `dotnet test` が全件通る

## 6. 人間に決めてほしいこと
| # | 質問 | AI の暫定案 |
|---|---|---|
| Q1 | 除外する語 | 冠詞・代名詞・前置詞・接続詞・助動詞・be/have/do などの機能語、数字・月以外の固有名・略語(例: mister, ok)、1〜2文字の語。短くても内容語(tax, law など)は残す。除外の一覧はレポートで確認できる |
| Q2 | Tier 1 の選び方 | Claude が英検準1級ライティング(社会問題の意見文)で使いやすい語を 500 語前後選ぶ。一覧はファイルで確認・修正できる |
| Q3 | 訳の確認のしかた | 作成後、ランダムに 100 語を抜き出して見てもらう。誤りの傾向があれば直してから全体を確定 |
| Q4 | 作業の分け方 | 1つの PR にまとめる(取得 → 統合 → 訳 → 穴あき → 検証)。PR #14(骨組み)のマージ後に出す |
