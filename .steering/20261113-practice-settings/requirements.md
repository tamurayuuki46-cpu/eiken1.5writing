# requirements.md — 練習設定の保存

## 1. 目的
- なぜやるか: 練習の基本設定(v1.2 2章 A)を毎回選び直す必要があり、settings.json はまだどこからも書かれない(v1.2 9章 Must「設定ファイルの保存・読込」「基本設定UI」、Should「初期値に戻す」)。
- 終わったときの状態(Outcome): 設定画面で基本設定を変えて保存すると、次の練習・次の起動でもその値が練習設定の初期値になる。初期値に戻せる。保存できないときは理由が分かり、学習記録は壊れない。

## 2. 範囲
- やること:
  - Flow: 設定画面の状態(`SettingsScreen`)と操作(開く・保存・初期値に戻す・閉じる)
  - ホーム・苦手一覧の画面の状態に、練習設定の初期値(保存済みの基本設定)を持たせる
  - Flow が SettingsRepository を持ち、起動時の読込結果で「保存できるか」を決める
- やらないこと:
  - WPF の画面(次のタスク)
  - 詳細学習設定(v1.2 2章 B)の画面と保存、単語別カスタマイズ
  - 練習を始めるときに選んだ値の自動記憶(ユーザー決定: 設定画面で保存したときだけ書く。練習ごとの選択は今までどおり書かない)
  - 設定ファイルの手動復旧

## 3. 機能要件
| # | 内容 | 優先度 | 入力 | 出力 |
|---|---|---|---|---|
| R1 | ホームから設定画面を開く。今の基本設定と選べる値(問題数・フラッシュ秒数の選択肢、手動モード)を出す | Must | 操作 | SettingsScreen |
| R2 | 保存: 基本設定(自動ミックス・手動モード・問題数・苦手のみ・フラッシュ秒数)を今の設定に重ねて検査し、settings.json に保存する。成功したらホームへ | Must | 基本設定 | ホーム(保存済みの文言) |
| R3 | 保存できないとき(不正な値・書き込み失敗)は設定画面に留まり、入力した値を残して理由を出す。もう一度保存か、保存せず閉じるを選べる | Must | 同上 | SettingsScreen(理由) |
| R4 | 新しい版の設定ファイル・読めない設定ファイルのときは、開いた時点で「保存できない」と理由を出し、保存を受け付けない | Must | 起動時の読込結果 | SettingsScreen(CanSave = false) |
| R5 | 初期値に戻す: 画面の値を基本設定の初期値にする(保存は R2 で行う) | Should | 操作 | SettingsScreen |
| R6 | 閉じる: 保存せずホームへ(何も書かない) | Must | 操作 | ホーム |
| R7 | ホーム・苦手一覧の画面に、練習設定の初期値として今の基本設定を持たせる | Must | — | Defaults |

## 4. 非機能要件
- Reliability: 設定の保存は学習記録に触れない。保存に失敗しても今の設定(メモリ)は変えない
- Compatibility: Schema 変更なし(settings.json の形は既存の LearningSettingsJson)。知らない項目・詳細設定は保存で失われない(今の設定に基本設定だけを重ねて保存)
- 進行中の練習には影響しない(セッションは開始時の設定を持つ。v1.2 7章)。設定画面は未完了の練習が無いとき(ホーム)からだけ開ける
- Privacy: 文言・Diagnostic にパスを入れない(既存の約束)

## 5. 受入条件
- [ ] ホーム → 設定 → 値を変えて保存 → ホームの初期値が変わる。作り直す(再起動)と同じ値が読まれる
- [ ] 保存した値で練習の初期値が決まり、詳細設定(例: retryCount)は保存の前後で変わらない
- [ ] 不正な値(範囲外の問題数など)は保存せず、設定画面に理由(項目)を出す。settings.json は変わらない
- [ ] 書き込みに失敗したら設定画面に留まり、入力した値と理由(Diagnostic つき)を残す。今の設定は変わらない。もう一度保存で成功する
- [ ] 新しい版・読めない設定ファイルでは CanSave = false、保存は受け付けず、ファイルは変わらない
- [ ] 壊れた設定ファイル(初期値で動いている)でも保存でき、壊れたファイルは退避名で残る
- [ ] 初期値に戻す → 画面の値が初期値になり、まだ書かない。保存で初期値が書かれる
- [ ] 閉じる・開く・初期値に戻す では何も書かない
- [ ] 受け付けない操作は例外で状態が変わらない
- [ ] `dotnet build -warnaserror` と `dotnet test` が全件通る
