# JSON 保存ルール

## 保存先
- 学習記録 `%APPDATA%\EikenSpelling\progress.json`、バックアップ `progress.bak.json`、設定 `settings.json`。
- 保存処理は Wpf 側の Repository だけが行う。Core はファイルに触れない。

## 保存の手順(v1.0 13.7)
1. 一時ファイルへ書き込む
2. 一時ファイルを読み戻して JSON を検証する
3. 既存ファイルを `.bak.json` に退避して置き換える
4. 保存成功を確認する
5. 成功してから進行状態を確定する(次の問題へ進む)
- 1問回答するたびに自動保存する。学習記録とセッション進行状態は1回の保存で一貫させる(13.2)。

## 二重記録の防止(v1.1 11章)
- 回答ごとに固定の `answerId`(sessionId + questionIndex + attemptType[normal / retry])を付ける。
- 同じ `answerId` は二重に加算しない。再保存では同じ `answerId` を使う。
- 保存に失敗したら次へ進まず、回答を保持して失敗を表示し、再保存できるようにする(13.3)。

## 破損時の復旧(v1.0 13.4・13.5)
- 主ファイルが壊れていたら、バックアップを検証し、正常なら自動復旧して通知する(一部記録が失われた可能性も伝える)。
- 壊れたファイルは消さずに残す。
- 両方壊れていたら元ファイルを保護し、勝手に初期化しない。「新しい記録で開始」「終了」を選ばせ、確認後にだけ新規作成する。
- 設定ファイルが不正でも学習履歴は壊さない。設定は初期値で補う(v1.2)。

## Schema 変更
- `schemaVersion` / `wordSetVersion` / `sourceVersion` を保存データに持つ(v1.1 4.3)。
- 変更の順序: 互換性確認 → バックアップ → マイグレーション → テスト。戻し方を design.md に書いてから着手する。
- 単語データを更新しても、単語 ID は固定のまま、既存の学習記録を保持する。
- 知らない項目は無視し、無い項目は初期値で補う(読み込みの互換性)。

## 禁止
- 保存ファイルの一括削除・初期化を確認なしで行うこと。
- テストで実際の `%APPDATA%` を読み書きすること(一時フォルダを使う)。
