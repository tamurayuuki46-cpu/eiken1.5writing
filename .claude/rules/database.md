# DB・データルール

## Schema 変更(駆動 A.1.6 マイグレーション規律)
- 既存のマイグレーションは書き換えない。変更は新しいマイグレーションで行う。
- 順序: 互換性確認 → バックアップ → マイグレーション → テスト。
- 戻し方(ロールバック)を design.md に書いてから着手する。
- Schema のバージョンを {どこ} で管理する。

## 保護の分担
- DB側で守る: {NOT NULL / 一意制約 / 外部キー}
- アプリ側で守る: {入力チェック / 権限チェック}
- どちらで守るか迷ったら design.md に書いて確認を取る。

## 禁止
- 本番・デプロイ環境のDBへの接続、データの一括削除。
