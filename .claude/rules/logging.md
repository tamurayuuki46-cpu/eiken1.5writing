# ログルール

<!-- 駆動 付録A にログルールの見本あり。要点ノートには細部が無いので、以下は一般的な運用案 -->

## 形式
- 構造化ログにする(キーと値)。最低限: 時刻 / レベル / 処理名 / {リクエストID などの追跡キー}
- レベル: error=要対応 / warn=想定外だが継続 / info=主要な処理の区切り / debug=開発時のみ

## 書かないもの
- パスワード・トークン・APIキー・個人情報。必要ならマスクする。

## 書く場所
- エラーは握りつぶさない。捕まえたら、原因が分かる情報と一緒に error で出す。
- 調査用の一時ログは、作業が終わったら消す。
