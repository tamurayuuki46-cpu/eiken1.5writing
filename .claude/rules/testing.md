# テストルール

## 書き方
- フレームワークは xUnit(`tests/EikenSpelling.*.Tests/`。Core・Persistence・Flow・Presentation)。テスト名は「条件_結果」が読める英語にする。
- 先に失敗すること(Red)を確認してから通す。最初から通ったテストは疑う(駆動 A.4 ステップ5)。
- 境界値を前後で押さえる。例: reviewLimits の区切り(5/6・10/11・20/21問)、克服回数・苦手度の上限(n-1 / n / n+1)。
- 正常系だけでなく、異常系(壊れた JSON・不正な設定・空データ)と「できないこと」も確認する。
- 時刻は `TimeProvider` で渡す(テストでは固定時刻の実装を使う)。日付の境目は日本時間 0:00 の前後で確かめる。乱数も引数で渡す。
- 学習ルールの値は `LearningSettings` から取り、テストに数値を重複して書きすぎない。値を変えた設定でも動くことを確かめる。
- モックが増えたら、テストではなく実装の責務分離を疑う。
- ImmutableArray(と、それを持つ record)は Assert.Equal で参照比較になる。`.ToArray()` か SequenceEqual で中身を比べる(2回同じ誤りが出たため追加)。

## 禁止(無効なテスト)
- 中身のない骨抜きテスト / 環境変数で黙ってスキップ / モックだらけで何も検証しないテスト
- 固定時間の待機(`Thread.Sleep` / `Task.Delay`)。状態を待つ書き方にする。
- 実際の `%APPDATA%` やユーザーの保存ファイルを読み書きすること。一時フォルダを使い、後始末する。

## 実行
- 完了前に `dotnet test` を全件実行し、全通過の出力を見せる。
- 並列実行を止める設定を入れたら、理由をコメントで残す(AIが勝手に戻さないように)。
- Presentation の ViewModel は本物の Flow(一時フォルダ)で確かめる。時計は GetUtcNow と GetTimestamp を同じだけ進める手書きの時計を使い、受け付け開始のゲートを固定時間の待ちなしで確かめる。正当な操作の補助は「受け付け開始 → 0.3 秒進める → 実行」を既定にし、ゲートで止まる空振りを防ぐ。
