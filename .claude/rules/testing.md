# テストルール

## 書き方
- 先に失敗すること(Red)を確認してから通す。最初から通ったテストは疑う(駆動 A.4 ステップ5)。
- 境界値を前後で押さえる: {上限-1 / 上限 / 上限+1}。
- 正常系だけでなく、異常系と「できないこと」(権限がない操作が拒否される)も確認する。
- 時刻・乱数は引数で渡す。モックが増えたら、テストではなく実装の責務分離を疑う。

## 禁止(無効なテスト)
- 中身のない骨抜きテスト / 環境変数で黙ってスキップ / モックだらけで何も検証しないテスト
- 固定時間の待機(`sleep` / `waitForTimeout` など)。状態を待つ書き方にする。

## 実行
- 完了前に `{test}` を全件実行し、全通過の出力を見せる。
- 本番・デプロイ環境のDBには接続しない。課金・実送信を伴うテストは別コマンド `{test:external}` に隔離する。
- 並列実行を止めている設定には理由をコメントで残す(AIが勝手に戻さないように)。
