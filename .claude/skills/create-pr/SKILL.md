# PR作成

## 事前確認(1つでも満たさなければ止めて報告)
- 現在のブランチが main ではない。
- `{lint}` / `{typecheck}` / `{test}` がすべて通る(出力を見せる)。
- レビュー役3体(design / edge-case / security)の P0・P1 が残っていない。

## セルフレビュー(5観点)
1. 設計: design.md どおりか、不要な変更が混ざっていないか
2. 機能: 受入条件を満たすか
3. 複雑さ: もっと単純に書けないか
4. テスト: 変更に対応するテストがあるか
5. 命名とコメント: 意図が伝わるか

## PR本文
```
## 目的
{requirements.md の目的を1〜2行}

## 変更点
- {}

## 確認したこと
- {テスト・手動確認の結果}

## 未解決・注意点
- {blockers / P2 の残り}

関連: .steering/{YYYYMMDD}-{タスク}/
```

## 作成
- `gh pr create --title "{}" --body-file {一時ファイル}` で作る。
- 作ったPRのURLを報告する。マージはしない(人が判断する)。
