# 設計の決定事項(実装で使う値の早見表)

正式な仕様は「統合設計仕様書 v1.0」「v1.1 変更提案レビュー」「v1.2 学習設定のカスタマイズ対応」。
ここには、仕様書を読まなくても実装・レビューできるように、コードに入っている決定だけを書く。

## 収録語数とデータ
- 約5,000語(NGSL 1.2 / NAWL 1.2 / BSL 1.2、いずれも CC BY-SA 4.0)。正確な語数は統合後に確定
- 単語IDは固定。重複語は1件に統合し、出典は配列で持つ
- 穴あき位置は自動生成。手動指定(`blankSource: manual`)が優先
- 日本語訳の辞書は未確定(ライセンス確認待ち)

## 学習設定(v1.2)
- 学習ルールの値は `LearningSettings` に置き、ロジックは受け取った設定で動く
- 初期値は `LearningSettings` の各プロパティ初期値に一本化(= v1.1 の決定値)
- 設定ファイルに無い項目は初期値で補い、知らない項目は無視する
- モード比率は辞書ではなく4項目の型(`ModeWeights`)。キーの欠けで重み0になる事故を防ぐため
- settings.json の形は実装の形を正式とする(2026-11-13。v1.2 6章の例は「実装前に確定」とされていた)
  - 項目名は camelCase。列挙値は型名どおりの文字列(`"Japanese"`, `"AfterNormalQuestions"`, `"TierThenFrequency"`)。読込は大文字小文字を区別しない
  - `reviewLimits` は配列 `[{ "upTo": 5, "limit": 1 }, ...]`(v1.2 例のオブジェクト `{"5":1}` 形式は読めない)
- 読込で InvalidDataException にするもの(settings.json・words.json 共通):壊れた JSON、型違い、桁あふれ、未知の列挙文字列、
  明示的な `null`(項目にもリストの要素にも。ただし null を許す項目 words.json の `blanks`・`frequencyRank` は null で正しい)、words.json の必須項目(id・word)の欠け。呼び出し側は InvalidDataException だけを捕まえればよい
  - 「無い項目は初期値」と「null は不正」は区別する(null は手書きの誤りとみなす)
- 設定値として受け付ける範囲(`SettingsLimits`、学習ルールではなく安全のための範囲):
  問題数・その選択肢 1〜100、モードの重み 0〜100、再練習回数 0〜3、フラッシュ表示 0.1〜10秒(選択肢も同じ)、再確認間隔 1〜3650日
- 定義外の列挙値(JSON の数値 `"manualMode": 99` など)は SettingsValidator が指摘する

## 保存・復旧(2026-11-13)
- progress.json = `{ schemaVersion, wordSetVersion, sourceVersion, progress, session? }`(schemaVersion の正本は ProgressDocument。Application に置く)
- 保存: tmp に書いて Flush(true) → 読み戻して変換・検査 → File.Replace(tmp, 主, bak)(初回は移動)。入出力の失敗は最大3回再試行
- 読込の結果: Loaded / FirstRun / RecoveredFromBackup / BothCorrupt / NewerVersion / Unavailable。後ろ3つは何も書き換えない
- 復旧は「bak の中身を tmp へ → 壊れた主を退避名へ移動 → tmp を主へ」。壊れたファイルは `<元の名前>.corrupt-<日時ミリ秒>[-n].json` で残す(上限なし)。残った tmp は `.orphan-<日時>` で残す
- 学習記録の検査(ProgressValidator): 重大は読込失敗と同じ扱い、警告は読めるが知らせる。50MB を超えるファイルは壊れている扱い
- 新しすぎる版: progress は保存・新規開始を拒否。settings は初期値で動かし、設定の保存を拒否
- settings.json が壊れている・値が不正 → 初期値で動かす(ファイルは書かない)。その後の保存では壊れたファイルを退避してから保存
- 呼び出し順: 設定の Load → 学習記録の Load。保存先フォルダは絶対パスだけ
- 二重起動は WPF で防ぐ(名前付き Mutex。2つ目は既存の画面を前に出して終了)。Persistence はアプリが1つだけ動いている前提
- 限界: Windows の File.Replace が途中で止まると、最後の1問分が orphan の tmp にだけ残ることがある

## セッション(2026-11-13)
- 出題一覧(単語ID・綴り・モード・使えるモード)を受け取って始める。開始時の設定を丸ごと保存し、途中で設定を変えても使わない(v1.2 7章)
- 通常問題と再練習を1本の列で持ち、列の位置が通し番号(questionIndex)。位置・再練習回数は保存しない
- 再練習: 通常問題をすべて終えた後、誤答した単語を通常問題の順に。正解するまで最大 RetryCount 回(2回目以降は列の最後)。
  モードは手動なら同じ、自動ミックスなら 日本語 → 音声 → 穴あき → フラッシュ の順で元以外かつ使える最初のもの(無ければ同じ)。単語ごとに最初に決めて以後も同じ
- 回答済みは {正誤, 状態の変化} だけ持ち、入力は持たない。完了・中止したセッションは保存しない(Session = null)
- answerId は未完了のセッションの分だけ残す(完了・中止の時点と読込時に整理)
- 保存失敗時の約束: 呼び出し側は SessionManager.Answer が返した学習記録とセッションを保存し直す。Answer を同じ問題でもう一度呼ばない(呼ぶと重複として例外)
- 読込でセッションに不備があれば、セッションだけ捨てて知らせる(学習記録は読む。元のファイルの写しを退避名で残す)
- 古い版のアプリで開くと session は無視され、次の保存で消える(学習記録は残る)

## 仕様からの差分
- 保存処理は v1.2 4章の図(`EikenSpelling.Wpf/Persistence`)ではなく、独立した `EikenSpelling.Persistence`(net10.0)に置く(2026-11-13)。本物のファイルで Linux と Windows の両方でテストするため。仕様書は直していない

## 層の依存
- Core の中は `Application → Domain / Settings → Models`。苦手度・克服の判定のため **Domain → Settings の参照は認める**(2026-11-13、v1.2 4章)
- Settings は Domain を参照しない

## 固定ルール(設定にしない)
- 正誤判定:大文字・小文字を区別しない、前後の空白を無視、途中の空白は無視しない
- 日付:日本時間(固定 +9:00)。Core は `TimeProvider` から時刻を受け取る
- 克服対象モード:日本語・音声(v0.1 は固定。`MasteryRules`)
- 誤答入力は 100 文字まで記録する(`InputRules`。サロゲートペアの途中で切らない)

## 出題枠
- 新規・苦手の端数は新規側に切り上げ(5問 → 新規3・苦手2)
- 再確認は苦手枠の一部と入れ替える。上限は区切り形式 `reviewLimits`
  (問題数 ≤5 → 1、≤10 → 1、≤20 → 2、それより多い → 最後の区切りの値)
- 自動ミックスは最大剰余法。同点は 日本語 → 音声 → 穴あき → フラッシュ
  - 例:10問 3/3/2/2、5問 2/1/1/1、20問 6/6/4/4、音声なし10問 4/0/3/3

## 差分表示
- Levenshtein 距離から編集手順を復元
- 同点のときは 置換 → 不足 → 余分 → 一致 の順で選ぶ
  - 入れ替わり(recieve)は「2文字違い」として表示
  - 同じ文字が続く箇所の不足は後ろ側で表示(accomodate → 「6文字目のmが不足しています」)

## 学習記録・克服・再確認(2026-11-13)
- 状態は 通常 / 苦手 / 克服済み の3つを保存。「未出題」は記録が無いこと、「再確認待ち」は 克服済み かつ 予定日 ≦ 今日 から求める
- 学習記録は変更不可。`AnswerRecorder.Apply` が新しい記録を返す
- answerId = sessionId(Guid、Empty は不可)+ questionIndex(再練習を含むセッション内の通し番号、0 以上)+ attemptType。同じ ID は1回だけ反映(再練習も)
- 苦手登録: 通常問題の誤答数の累計が `MarkWeakAfterMistakes` 以上。苦手・克服済みの単語は通常問題の誤答で必ず苦手(閾値を後から上げても外れない)
- 克服: 苦手の単語が、日本語・音声の通常問題で、最後の対象正答日より**後の日**(日本時間)に正答したら連続正答 +1。
  同じ日・前の日・穴あき・フラッシュの正答は何も変えない。通常問題の誤答で 0。同じ日の誤答のあとの正答はリセット後の1回目
- 克服時の連続正答は必要回数にそろえて残す(v1.1 10.3)。苦手に戻っても克服日時(MasteredAt)は残す
- 追加再練習の回答は記録(再練習の正答数・誤答数、最後の誤答入力、最終出題日時)だけ。状態・連続正答・再確認・苦手登録の累計に影響しない。記録の無い単語への再練習は例外
- 再確認: 予定日**以降**(当日を含む)に通常問題で正答したら、**モードを問わず**次の段階へ。次回日は**実際の回答日**+ 間隔。
  段階の上限は間隔の数(既定 3)。最後の段階は `RepeatLastInterval` なら同じ間隔、そうでなければ予定日なし。予定日より前の正答は記録だけ
- 期限一覧は予定日の古い順、同じ日は単語ID順。予定日は出題されるまで変えない(設定の間隔を変えても既存の予定日はそのまま)
- 正答率は通常問題だけ・モードごと。未出題は「未学習」(null)

## 苦手度(v1.1 7.2、設定値は `WeakWordScoreSettings`)
- **保留(2026-11-13)**: v1.1 7.4 に「まだFAではない」とあるため、計算は実装していない。下の式と `WeakWordScoreSettings` は案として残す
- min(通常問題の誤答数, 5) + 直近7日の誤答 +3 + 克服まであと1回 +2 + 最終通常出題から14日以上 +2
- 追加再練習の誤答は加算しない。同点は最終通常出題が古い順
