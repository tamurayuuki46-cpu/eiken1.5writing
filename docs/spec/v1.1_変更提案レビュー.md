1. 総合結論

収録語数を100語から約5,000語に拡張する方針に賛成。

ただし、Claudeの変更提案をすべて無修正で採用することは推奨しない。

特に以下の3項目は修正が必要。

1. 日本語訳の重複による自動除外
2. 苦手度の計算式
3. 新規単語の出題優先順位

C#・WPF・JSON保存・Core分離という基本構成は維持できる。

最大の課題は処理性能よりも、5,000語のデータ品質と出題の正確性である。

2. 収録語数の変更

2.1 変更内容

旧仕様：100語

変更提案：約5,000語

対象リスト：

リスト| 語数の目安| 主な用途
NGSL 1.2| 約2,800語| 一般英語
NAWL 1.2| 約960語| アカデミック英語
BSL 1.2| 約1,700語| ビジネス・社会テーマ

公式サイト：
https://www.newgeneralservicelist.com/

3リストはCC BY-SA 4.0で公開されている。

ただし、統合後の実際の収録語数は未確定。

2.2 統合処理

1. 3リストを読み込む
2. 英単語の表記を正規化
3. 重複を検出
4. 重複語を統合
5. 出典情報を保持
6. 簡単すぎる単語の除外候補を抽出
7. 日本語訳を付与
8. 出題可否を検証
9. 最終単語データを生成
10. 検証レポートを出力

正確に5,000語に合わせるための水増しは行わない。

2.3 短い単語の扱い

「3文字以下はすべて除外」というルールは推奨しない。

理由：

- tax
- law

など、短くてもライティングで使用する重要語があるため。

文字数だけでなく、使用可能性・頻度・スペル難度を考慮する。

3. ライセンス設計

3.1 語彙リスト

- NGSL
- NAWL
- BSL

各リストの配布元、バージョン、ライセンス、取得日を記録する。

3.2 日本語辞書

日本語訳の提供元は未確定。

辞書名を確定し、以下を確認する。

- 商用利用
- 改変
- 再配布
- 出典表示
- 更新義務・配布条件
- 他データとのライセンス互換性

EDICT/JMdictはパブリックドメインではなく、CC BY-SA 4.0で公開されている。

辞書のライセンスと語彙リストのライセンスを個別に管理する。

3.3 ソースコードとの分離

単語データとC#ソースコードは別ライセンスで管理できる。

推奨構成：

- アプリコード：独立したライセンス
- 単語データ：CC BY-SA 4.0の条件に従って公開
- 出典情報：アプリ内とリポジトリに表示
- ライセンス文書：リポジトリ内に保存

実際の公開条件は使用したデータのライセンスに従う。

4. 単語データ設計

4.1 追加項目

{
  "id": "accommodate",
  "word": "accommodate",
  "ja": "収容する・対応する",
  "blanks": "acc__modate",
  "sources": ["NGSL"],
  "priorityTier": 1,
  "frequencyRank": 1200,
  "japaneseEligible": true,
  "audioEligible": true,
  "blankSource": "manual"
}

※上記の出典・順位は構造説明用の仮値。

4.2 データ設計原則

- 単語IDは固定
- 単語IDを取り込み順に依存させない
- 重複語は1つのレコードに統合
- 出典は配列で保持
- 元リストの順位情報を保持
- 日本語モードの出題可否を管理
- 音声モードの出題可否を管理
- 自動生成と手動修正を区別
- 手動修正を自動生成より優先

4.3 バージョン管理

追加する項目：

- schemaVersion
- wordSetVersion
- sourceVersion

単語データ更新時も既存の学習記録を保持する。

5. 穴あき位置の自動生成

5.1 変更内容

旧仕様：100語の穴あき位置を手動指定。

新仕様案：約5,000語の穴あき位置をルールベースで自動生成。

5.2 自動生成ルール

主な対象：

- 二重子音
- 間違えやすい母音
- 黙字
- -able / -ible
- -ance / -ence
- その他の頻出スペルパターン

5.3 優先順位

1. 手動修正済みの穴あき位置
2. 自動生成ルールによる候補
3. 汎用的な穴あき位置

5.4 検証条件

- 元の単語と文字数が一致
- 穴あき部分を補えば元の単語に復元できる
- 不正な位置を指定しない
- 手動修正を勝手に上書きしない
- 生成不能の場合も不正な問題を出さない

6. 日本語・音声モードの出題適格性

6.1 日本語モード

同じ日本語訳を持つ単語を自動検出する。

ただし、重複しているという理由だけで永久に除外しない。

推奨処理：

1. 日本語訳の重複を検出
2. 対象単語を一時的に日本語モード不可にする
3. ヒントを手動確認・修正
4. 一意に特定できる場合は使用可能に戻す

日本語訳が重複していない場合でも、意味が曖昧なら除外する。

Q31のFA「曖昧な日本語問題は出題しない」は維持。

6.2 音声モード

同音異義語リストを使って出題不可の単語を検出する。

- 発音だけで正答を特定できない単語は除外
- 他の適格モードで出題
- 語彙データに出題可否を保持

Q32のFAを維持。

6.3 日本語・音声の両方が不可の場合

初期収録候補から除外する。

理由：

現在の克服判定は、日本語または音声モードでの自力正答を必要とするため。

端末に英語音声がない場合は、音声が必要な単語を自動診断から一時除外する。

7. 苦手度の計算式

7.1 Claude案

誤答回数（上限5）＋直近7日以内の誤答なら3点−克服用連続正答×2。

問題点

- 出題回数の多い単語ほど累計誤答が増えやすい
- 追加再練習の誤答まで含めると偏りが生じる
- 長期間出題されていない苦手単語を十分に考慮できない

7.2 修正推奨案

通常問題での初回回答を基本にする。

苦手度 =
  min(通常問題の累計誤答数, 5)
  + 最近7日以内の誤答なら3点
  + 克服判定待ちなら2点
  + 最終通常出題から14日以上経過なら2点

7.3 同点時

最後に通常出題した日時が古い順。

7.4 注意点

- 追加再練習の成績は記録する
- 追加再練習の誤答を苦手度に直接加算しない
- 苦手度は未克服単語の出題順に使用
- 克服済み単語は別の定期再確認ロジックで管理

※計算式は修正提案であり、まだFAではない。

8. 自動ミックスの端数配分

8.1 基本比率

日本語：音声：穴あき：フラッシュ

3：3：2：2

練習問題数| 日本語| 音声| 穴あき| フラッシュ
5| 2| 1| 1| 1
10| 3| 3| 2| 2
20| 6| 6| 4| 4

8.2 推奨計算方法

最大剰余法を採用する。

1. 利用可能なモードの比率を合計
2. 問題数に応じて理論値を計算
3. 整数部分を配分
4. 余りを小数部分の大きいモードから配分
5. 同率の場合は固定優先順位を使用

8.3 音声モードが利用できない場合

元の比率：

日本語3：穴あき2：フラッシュ2

10問の再配分：

モード| 問題数
日本語| 4
穴あき| 3
フラッシュ| 3

8.4 出題適格性の優先

単語によって特定のモードが使用できない場合は、モード比率よりも出題可能性を優先する。

比率は目標値であり、すべての環境で厳密な一致を要求しない。

9. 自動ミックスの再練習

9.1 基本動作

- 自動ミックスでは原則別モードで再練習
- 適格な別モードがない場合のみ同一モード
- 手動モードでは同じモードを使用
- 追加再練習は各誤答単語1回まで

9.2 克服判定

追加再練習の正答は、克服判定に使用しない。

11. 回答の二重記録防止

11.1 answerId

回答ごとに固定IDを付与する。

構成例：

sessionId + questionIndex + attemptType

attemptType：

- normal
- retry

11.2 保存ルール

- 同じ回答を二重加算しない
- 再保存時に同じanswerIdを使用
- 保存失敗時は回答データを保持
- 保存成功後に次の問題へ進む
- セッション進行状態と学習記録を一貫して保存

13. 日付・時刻の扱い

13.1 TimeProvider

Coreでは現在時刻を直接取得せず、TimeProviderから受け取る。

テストではFakeTimeProviderを利用可能にする。

13.2 克服判定

- 日本時間（JST）を基準
- 実際の回答日を使用
- セッション開始日は使用しない
- 異なる日に2回連続正答で克服
- 同じ日の複数正答は最大1回分
- 誤答した場合は連続正答をリセット

14. 新規単語の出題順

14.1 推奨方式

ライティング向け優先度 → 頻度順 → 同順位内でランダム

完全ランダムや単純な元リスト順は採用しない。

14.2 優先度分類

優先度| 対象
Tier 1| ライティングで特に使用しやすい重要語
Tier 2| NAWLの残り・関連性の高いBSL語など
Tier 3| その他の一般語・専門語

14.3 Tier 1

初期目安：300〜800語。

ただし正式件数は未確定。

英検準1級のライティングで使用する可能性を基準に選ぶ。

NAWLという理由だけで、すべてTier 1にはしない。

14.4 Q11との整合性

新規50％＋苦手50％のFAを維持する。

毎日1セッション実施した場合の単純計算。

問題数| 新規語数/日| 5,000語一巡
5問| 3語| 約1,667日
10問| 5語| 約1,000日

これによって重要語への到達を早める。

20. 最終結論

収録語数を約5,000語へ拡張する変更は合理的。

ただし、約5,000語を収録することと、約5,000語すべてを同じ優先度で学習することは区別する。

最重要原則：

1. ライティングに必要な単語を優先する
2. 苦手単語を正確に発見する
3. 苦手単語を集中的に反復する
4. 克服済み単語を定期的に確認する
5. 学習記録の信頼性を維持する
6. 不適切な出題で誤答を増やさない

「5,000語を全部覚えること」ではなく、「必要な語のスペルを正確に書けること」を優先する。
